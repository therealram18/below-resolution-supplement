## A. Chronos Benchmark II without results on datasets a model was trained on

**Flags.** Column `trained_on_this_dataset` in `benchmarks/chronos_zeroshot/results/*.csv`. Count confirmed: 74 of 567 (entry, task) results: moirai_small 22, moirai_base 22, moirai_large 22 (the same 22 tasks), timesfm 4 and timesfm-2.0 4 (m4_quarterly, m4_yearly, monash_traffic, monash_weather). These cover 22 of the 27 tasks; the 5 tasks without any flag are ETTh, ETTm, dominick, ercot, exchange_rate (4 sources: ETT, dominick, ercot, exchange_rate).

**What the fev library does** (`boards/fev/src/fev/analysis.py`, commit 9cf943c). `leaderboard` reads the flag into `training_corpus_overlap_df` (line 311-313) and acts on it only if the caller names a replacement model:

- signature, line 237: `leakage_imputation_model: str | None = None`
- docstring, lines 270-271: "Zero-shot model used to replace results when data leakage is detected. Applied before `missing_strategy`."
- lines 332-333: `if leakage_imputation_model is not None:` then `errors_df = _handle_leakage_imputation(...)`
- line 225: `return errors_df.mask(training_corpus_overlap_df, errors_df[leakage_imputation_model], axis=0)`

So with the default the flag is ignored (this is what the first round did). When a model is named, each flagged cell is replaced by that model's score on the same task (already divided by the baseline); the library raises an error if the named model is itself flagged anywhere. The library never drops flagged tasks or entries. The only place the repository names a replacement model is `scripts/generate_fev_bench_figures.py` line 57 (`"Chronos-Bolt"`, for fev-bench; its metadata points to chronos-bolt-base). Chronos Benchmark II has no script or table in the repository, so there is no published choice for it.

**Primary (library handling).** Replacement model: `chronos_bolt_base` (the same model fev-bench uses; it has no flagged cell). Check: calling `fev.analysis.leaderboard(..., leakage_imputation_model="chronos_bolt_base", task_columns="task_name")` gives the same order as my matrix, maximum win-rate difference 2.2e-16. One mechanical effect: on 22 of 27 tasks each of the three Moirai entries (and on 4 tasks both TimesFM entries) now has exactly the score of chronos_bolt_base, so they tie with it there (ties count 0.5 in win rate, average rank in mean rank). Rank is computed on the replaced MASE (equal to ranking the replaced relative errors, same baseline per task). **Secondary:** drop the 22 tasks with at least one flag, for all entries: 5 tasks, 4 sources, 21 entries.

## C. TSFM-Bench and TS-Arena

Inspected 2026-11-13. Listings only; one sample file (578 KB) and one manifest (603 KB) in `boards/scout_round2/ts_arena/sample/`, plus the two API file listings (18 MB of JSON) in `boards/scout_round2/ts_arena/`. No score was aggregated or compared.

### TSFM-Bench
- URL: https://github.com/decisionintelligence/TSFM-Bench (branch master, last commit f9bb694, 2026-03-10); paper arXiv 2410.11802 (KDD 2025, v6).
- Published: code only (1,279 files in the tree: 754 shell scripts, 275 Python files, 10 JSON files which are run configs and `dataset/instruct.json`, no CSV, parquet or xlsx). The README gives no leaderboard and no result files; the datasets and environment are Google Drive links. Results appear only in the paper's tables. No hosted leaderboard found by web search (the search returned the paper and an unrelated board, FUTURE-TS). No version history of results.
- Sort rule, sources, download size: none to state (nothing to sort). Per-(entry, unit) scores are not published; the first-round report cannot be run on it. Running it would need re-running the models (GPU work, not covered) or typing paper tables by hand, which gives aggregates per dataset only for the models in the paper.

### TS-Arena
- URLs: live board https://ts-arena.live (also HF space DAG-UPB/TS-Arena, prototype); paper arXiv 2512.20761; data https://huggingface.co/datasets/DAG-UPB/TS-Arena-Archive and https://huggingface.co/datasets/DAG-UPB/ts-arena-context-mase-splitted.
- **Per-unit scores exist.** `ts-arena-context-mase-splitted` (cc-by-4.0, sha a2d8e4d, modified 2026-07-13, 340 files, 1.64 GB in total of which `mases/` is about 147 MB): Hive-partitioned parquet, `{train,test_time,test_heldout}/mases/unique_id=<series>/part-*.parquet`. The README says year_month and round_id are also path partitions, but in the sample file they are columns; sample file columns `year_month, round_id, model_id, model_name, mase` (the series id is in the path). One row per (model, series, round). Sample file: 9,911 rows, 35 distinct model names. Manifest `round_split.csv`: `round_id, schedule_id, registration_start, split`; 7,670 rounds (4,380 train, 2,192 test_time, 1,098 held-out Fingrid). 84 distinct series ids (75 in train, 75 in test_time, 9 in held-out). Context files (input windows) are the other 1.5 GB and are not needed for scoring.
- `TS-Arena-Archive` (sha 72c6cb0, 2026-06-18, 46,354 files, 3.80 GB): `forecasts/` 40,320 parquet files, 3.51 GB (one per schedule / round start / model; 14 schedules, 32 model names), `context_data/` 245 MB, `ground_truth/` 41 MB. Contains forecasts and truth, so scores could be recomputed; MASE already exists in the other dataset. No column header was read from it.
- Entries: 32 model names in the archive forecasts (35 in the MASE sample file, so the MASE set is not identical). The live board has Reference and Open tracks and monthly snapshots ("Backtesting Archive" page); a version history of the board exists only as monthly snapshots on the site, and of the datasets as HF git history (not examined).
- Displayed sort rule: Arena Score, higher better, with 95% interval and a range of possible places (from the page); the paper describes an Elo-type rating from pairwise comparisons of MASE per challenge round (a model wins a round if its score is lower; the paper does not give the update equation, and uses a bootstrap that permutes round order). The page also shows MASE and SQL over the last 30 days. The Arena Score from the live page could not be reproduced without the method; the Elo order depends on round order.
- Natural units and sources: unit = (series, round) with its MASE, or (schedule, round) if ratings are per model per challenge round as the paper says (it averages MASE over the series in a round). Natural sources = the 14 schedules / challenges (provider + target + horizon: fingrid, gridstatus generation / hub zone / load, smard dam / generation / load, each with 24h-15min and 72h-1h), or the 7 providers-targets pairs; rounds of the same schedule are strongly dependent, so the schedule is the cluster. Alternatively the 84 series.
- Download size needed for the first-round report: about 147 MB for the `mases/` files plus the 0.6 MB manifest (selective download), versus 1.6 GB for the whole MASE dataset.
- Could the report be run? Per-unit scores exist, so yes in principle, but needs before any analysis: a decision on the displayed rule (the Elo-type Arena Score is neither a mean nor a win rate, and no code was found in the datasets to reproduce it), a dated PREREG_BOARDS note, handling of models missing from some rounds (35 names in one file, rounds start at different dates), and the dependence between rounds (very few independent sources, 14 schedules). Not done in this round (the spec forbids analysis here).
